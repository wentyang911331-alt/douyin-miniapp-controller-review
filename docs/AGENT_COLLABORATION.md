# 子代理协作文档

## 协作目标

通过 UI 子代理和前端子代理分别产出专业建议，由主控统一合并，保证页面调整既符合测评报告的视觉目标，也符合原生抖音小程序的代码口径。

当前阶段不需要后端子代理。

## 角色分工

### 主控

主控负责：

- 维护项目规范和需求边界
- 调度 UI 子代理与前端子代理
- 合并两个子代理的建议
- 识别冲突并给出取舍
- 在用户确认前阻止对运行代码的修改
- 最终实施代码改动和验证

### UI 子代理

UI 子代理负责：

- 测评报告风格定义
- 标题、水印、说明入口、居中弹窗的视觉方案
- 表格和排行榜的信息层级
- 移动端阅读体验
- 暗色和亮色模式下的视觉一致性
- 细节建议，包括间距、字号、边框、按钮状态、提示样式

UI 子代理不直接修改代码，先输出方案。

### 前端子代理

前端子代理负责：

- 当前原生小程序页面结构分析
- 居中弹窗交互方案
- 水印恢复方案
- 小程序约束下的代码整理建议
- 风险点识别
- 验证方式建议

前端子代理不直接修改代码，先输出方案。

### 后端子代理

当前不启用后端子代理。

只有出现以下需求时再启用：

- 数据改为接口拉取
- 需要后台配置或内容管理
- 需要用户登录、权限或账号状态
- 需要提交测试数据
- 需要服务端生成报告、图片或分享内容
- 需要埋点上报或远程统计

## 协作流程

1. 主控确保需求文档已落地，并明确版本号和开发边界。
2. 前端子代理优先启动，负责实现方案、风险清单和验证建议。
3. UI 子代理按需介入，主要处理配色、弹窗、水印和图标细节。
4. 主控合并 UI 和前端方案，形成实施计划。
5. 用户确认实施计划。
6. 主控修改当前版本运行入口代码。
7. 主控完成验证并更新必要文档。

## 子代理输出格式

每个子代理输出应包含：

- 结论摘要
- 建议清单
- 风险或待确认点
- 对另一个子代理的协作提醒

UI 子代理应额外包含：

- 视觉优先级
- 组件状态说明
- 移动端注意事项

前端子代理应额外包含：

- 代码改动范围
- 小程序迁移影响
- 验证清单

## 冲突处理

当 UI 建议和前端建议冲突时，按以下顺序决策：

1. 不破坏现有核心功能
2. 不影响移动端阅读
3. 不增加小程序迁移难度
4. 不引入不必要依赖
5. 保持测评报告风格

无法判断时，由主控整理为待确认问题交给用户确认。
