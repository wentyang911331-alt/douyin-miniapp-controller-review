# 需求文档

## 背景

项目中目前有一个原始静态 HTML 文件：`controller-review(1).html`。它用于展示控制线横向测试结果，页面内置静态数据、样式和交互逻辑。

当前已完成 1.1.0 页面实现。后续需求仍先沉淀到文档，再按版本进入实现。

## 版本范围

- 当前版本：1.1.1
- 版本标签：`v1.1.1`
- 版本目标：完成原生抖音小程序项目迁移
- 备份要求：每个版本都需要推送到 GitHub，并保留可回滚的版本标签

## 1.1.1 已实现需求

### 版本目标

1.1.1 版本目标是将当前 1.1.0 静态 HTML 页面迁移为符合抖音标准的原生抖音小程序项目。该目标已完成。

本版本不再以 HTML 文件作为运行入口，也不使用 `web-view` 包裹 H5 页面。当前 `controller-review(1).html` 作为历史基线和对照页面保留，小程序运行入口改为原生小程序文件。

### 原生小程序项目结构

1.1.1 已新增以下结构：

```text
app.js
app.json
app.ttss
project.config.json
pages/controller-review/index.ttml
pages/controller-review/index.ttss
pages/controller-review/index.js
pages/controller-review/index.json
assets/icons/
```

页面路径需要在 `app.json` 中声明。页面由 `.ttml`、`.ttss`、`.js`、`.json` 组成，符合抖音小程序原生页面结构。

### 功能迁移范围

1.1.1 已从 1.1.0 迁移并保留以下能力：

- 标题：`2026 年春季控制线横屏对比手册`
- 页面级弱水印：`小拓子横评`
- 六个测试模块和静态测试数据
- 每个模块的说明图标和说明小浮窗
- 圆角线性 SVG 图标体系
- 产品高亮
- 主题切换
- 最佳徽章开关
- 排名角标开关
- 列显示控制
- 表格视图
- 排行榜视图
- 排序逻辑
- 九号 M395C 原厂作为参考项，不参与改装产品排名

### 继续移除的功能

以下功能在 1.1.1 中继续保持移除，不恢复：

- 聚焦模式和非高亮产品变暗逻辑
- 录制模式
- 截图按钮和截图提示入口

### 技术迁移要求

1.1.1 已从浏览器 HTML 写法迁移为小程序原生写法：

- 不使用 `window`
- 不使用 `document`
- 不使用 `innerHTML`
- 不使用浏览器 `localStorage`
- 不使用原生 HTML `table` 作为核心结构
- 不引入第三方前端依赖
- 不使用 `web-view`

页面结构使用抖音小程序组件，例如 `view`、`text`、`scroll-view`、`button` 等。交互使用 `bindtap`、`data-*`、`Page` 和 `this.setData`。

静态数据当前先放在页面 `index.js` 中，后续如数据量继续增大，再考虑拆分为更细的数据文件。

### 样式要求

- 使用 TTSS
- 移动端优先
- 优先使用 `rpx`
- 保持测评报告风格
- 保留 1.1.0 的暗色视觉基调和亮色主题能力
- 表格区域使用横向滚动容器模拟表格阅读体验
- 首列固定效果如原生小程序实现成本过高，可以先用可读性优先的横向滚动方案替代，并在实现方案中说明取舍

### 本地状态

1.1.0 中的浏览器 `localStorage` 状态已迁移为抖音小程序本地缓存能力，使用 `tt.getStorageSync` 和 `tt.setStorageSync`。

需要保存的状态包括：

- 主题
- 高亮产品
- 最佳徽章开关
- 排名角标开关
- 当前分区
- 各分区视图、排序、隐藏列等状态

说明小浮窗的打开状态不需要持久化。

### 后端判断

1.1.1 仍然不需要后端。

理由：

- 数据继续静态内置
- 不需要用户登录
- 不需要远程配置
- 不需要提交数据
- 不需要后台管理
- 不需要服务端生成报告

如后续出现动态数据、后台配置、账号权限、数据提交或服务端生成图片/报告需求，再重新评估后端子代理。

### 验收标准

1.1.1 验收标准：

- 可以作为抖音小程序项目被开发者工具打开
- `app.json` 页面路径配置正确
- 页面首屏正常渲染
- 六个模块都能展示
- 横向数据区域可滚动阅读
- 表格视图和排行榜视图可切换
- 排序功能可用
- 产品高亮可用
- 主题切换可用
- 最佳徽章开关可用
- 排名角标开关可用
- 列显示控制可用
- 六个说明小浮窗可打开和关闭
- 聚焦、录制、截图功能没有恢复
- 控制台没有明显运行错误
- 更新 `VERSION`、`CHANGELOG.md` 和相关项目文档
- 提交、打 `v1.1.1` 标签并推送 GitHub 备份

### 实施前确认结果

以下口径已确认：

- 接受保留 `controller-review(1).html` 作为历史基线和对照页面，不再作为 1.1.1 运行入口
- 接受静态数据先放在小程序前端代码中
- 接受横向滚动方案优先保证可读性，首列固定根据原生实现成本决定
- 1.1.1 暂不加入抖音小程序 `appid`，先使用开发者工具测试号或空配置
- 继续由主控调度前端子代理，UI 子代理只在迁移后出现明显视觉偏差时再介入

## 已确认需求

### 标题

将页面标题统一调整为：

> 2026 年春季控制线横屏对比手册

后续实现时，需要同步处理浏览器标题、页面顶部标题，以及如有需要的分享标题或小程序导航标题。

### 水印

水印文字为：

> 小拓子横评

建议实现方式为页面级弱水印，覆盖内容区域，低透明度，不遮挡表格和排行榜阅读。

### 测试说明

为页面现有六个模块分别增加说明。说明不直接展开在页面中，而是通过模块标题旁的信息图标触发小浮窗展示。

六个模块为：

- 硬件规格对比
- 交互软件与辅助功能
- 日常骑行手感（模拟跟车）
- 10km 温控限流路径
- 稳定输出区耗电对比
- 加速性能横评

说明文案由主控先拟定，重点解释指标含义、测试口径、排名边界和参考项处理方式。

### UI 方向

整体 UI 方向为测评报告。

后续细节调整应优先增强：

- 报告标题感
- 模块层级
- 数据阅读效率
- 小浮窗说明体验
- 水印存在感但不干扰阅读
- 移动端横向表格阅读体验

### 图标统一

页面内所有图标需要统一视觉风格。

后续实现时应采用统一的圆角图标体系，避免混用不同风格的文字符号、尖角符号或不一致的图形。图标按钮建议保持同一套尺寸、圆角、线条粗细、留白和激活态样式。

UI 验收已通过：采用「圆角容器 + 圆角线性 SVG」。最佳徽章采用「星标 + 最佳」，排名角标保留 `#1/#2/#3`。

涉及范围包括但不限于：

- 顶部工具图标
- 模块信息图标
- 小浮窗关闭图标
- 列显示图标
- 排序图标
- 主题切换图标

### 功能移除

后续实现阶段需要移除以下功能：

- 移除聚焦模式：即右上角用于让非高亮产品变暗的隐藏功能。产品高亮能力本身保留，但不再提供“非高亮产品变暗”的开关。
- 移除录制功能：页面不再提供录制模式入口、退出录制按钮、录制模式状态和相关样式。
- 移除截图功能：各模块右侧不再提供截图按钮，也不保留“请使用系统截图”的提示入口。

### 小程序准备

当前不正式迁移为抖音小程序项目，仍保留 HTML 展示形态。

后续实现需要尽量按抖音小程序落地方向约束：

- 保持移动端优先
- 让数据、状态、展示逻辑更清晰
- 交互尽量状态驱动
- 样式便于未来拆为 TTSS
- 不新增难迁移的浏览器专属能力

## 当前非目标

以下内容不是当前阶段目标：

- 不接入后端接口
- 不引入数据库或后台管理
- 不重做测试数据
- 不新增第三方前端依赖

## 后端判断

当前不需要后端。

理由：

- 数据全部静态内置
- 页面不需要登录或用户状态
- 页面不需要远程配置
- 页面不需要数据提交
- 页面不需要后台编辑能力

如后续出现动态数据、接口拉取、账号权限、后台配置、数据管理或埋点上报需求，再重新评估是否增加后端子代理。

## 1.1.0 历史确认结果

以下口径已在 1.1.0 实现阶段确认并落地：

- 水印采用页面级弱水印
- 小浮窗通过模块说明图标打开，通过关闭按钮关闭
- 说明文案采用主控拟稿
- 保留主题切换、高亮、排行榜等核心功能
