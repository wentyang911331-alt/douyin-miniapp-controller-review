# 需求文档

## 背景

项目中目前保留一个原始静态 HTML 文件：`controller-review(1).html`。它用于展示控制器横向测试结果，页面内置静态数据、样式和交互逻辑。

当前已完成 1.1.5 标题 / logo 与进入页 loading 版本。1.1.6 从 `v1.1.5` 继续推进价格信息移除需求。

## 版本范围

- 当前版本：1.1.6
- 当前开发分支：`codex/v1.1.6-remove-prices`
- 代码基线：`v1.1.5`
- 版本目标：在 UI 视觉完全不改的前提下，移除当前小程序运行界面的所有价格相关内容
- 备份要求：每个版本都需要推送到 GitHub，并保留可回滚的版本标签

## 1.1.6 需求口径

1.1.6 只做价格信息移除，不做 UI 换肤。

### 核心目标

- 当前小程序运行界面不再展示任何价格相关内容。
- UI 视觉完全不改：颜色、图标、间距、圆角、loading、弹窗、深浅模式和导航样式均不做换肤调整。
- 数据展示结构只做必要收口：删除价格字段后，其余硬件规格字段顺序自然前移。

### 具体范围

- `硬件规格对比` 表格删除价格列。
- `显示列` 面板删除价格选项。
- 表格排序、排行字段和排序 chip 不再出现价格。
- 硬件模块默认排序改为 `峰值母线`。
- 兼容旧缓存中保存过 `price` 排序或隐藏列的情况，自动清理无效字段并回落到有效排序列。
- 当前运行入口不得出现 `价格`、`price`、金额 + `元` 的展示。

### 明确边界

- `controller-review(1).html` 保留为历史基线，不删除，不作为 1.1.6 运行入口和验收对象。
- 不修改产品代表色、排行榜颜色、业务判断颜色规则。
- 不新增后端接口、不新增依赖、不接入远程数据。
- 不改变标题、logo、loading、水印、说明弹窗等 1.1.5 既有能力。

### 验收方式

- 运行 `node scripts/verify-v1.1.6-remove-prices.js`。
- 在抖音开发者工具中预览时，硬件表格、显示列、排行 / 排序入口均不能看到价格。
- 如本地存在旧缓存，仍应自动回落到 `峰值母线` 排序，不应出现空白、异常或价格字段回流。

## 1.1.5 需求口径

1.1.5 包含两类需求：原生导航栏标题 / logo 调整，以及进入页面 loading 动画。

### 标题与 logo

- 用户圈选的位置是抖音小程序原生导航栏区域，不是页面 TTML 内的顶部标题区。
- 原生导航栏左侧圆形小程序 logo 属于平台控制，不通过页面代码替换；如需变更，需要在抖音开放平台的小程序品牌 / logo 配置中处理。
- 代码侧将原生导航栏标题文字从 `2026年春季260级控制器对比手册` 改为 `摩拓`。
- 页面正文内的大标题 `2026年春季260级控制器对比手册` 暂不修改，避免影响报告内容识别。
- 已处理用户提供的 SVG 图标，保留圆形 logo mark 资源：
  - `assets/brand/motuo-mark-dark.svg`
  - `assets/brand/motuo-mark-light.svg`
  - `assets/brand/motuo-mark-app-icon.png`
- 深色模式圆形 logo 使用主题蓝 `#5E7BFF`，明亮模式圆形 logo 使用主题蓝 `#3B54D6`；图形内部保持白色。
- `motuo-mark-app-icon.png` 为 1024 x 1024 透明背景 PNG，用于开发者工具或开放平台需要上传小程序头像 / logo 时使用。
- 原生导航栏标题 `摩拓` 的文字颜色继续通过 `navigationBarTextStyle` 和 `tt.setNavigationBarColor` 控制：深色模式白色前景，明亮模式黑色前景。

### 进入页 loading

- 进入页面时需要展示 loading 动画。
- 即使页面可以秒加载，也必须至少展示 1 秒 loading。
- 如果页面真实加载超过 1 秒，loading 需要持续到真实加载完成后再关闭。
- loading 背后需要对主页面做高斯模糊或等效压暗处理，让焦点停留在 loading 动画上。
- loading 视觉由设计侧交付代码，交付物可能包含 HTML / CSS / JS；前端落地时需要转译为抖音小程序可用的 TTML / TTSS / JS，不直接照搬浏览器 DOM API。
- 设计交付代码不得依赖 `window`、`document`、`innerHTML`、外链脚本、远程字体或浏览器专属动画库。
- loading 动画应可在深色 / 明亮模式下识别，并使用 1.1.5 品牌圆形 logo 的同一套图形和主题色口径。
- loading 关闭后不改变当前页面数据、排序、高亮、主题、列显示等已有状态。
- 当前已将 UI 交付包中的 loading 结构转译进原生小程序页面：使用 TTML view / canvas 结构、TTSS keyframes 和页面 JS 状态机实现，不使用 inline SVG / 浏览器 DOM。
- logo 笔画优先使用 Canvas V2 按 UI 包坐标绘制；不支持 canvas 节点时使用 view 组合动画兜底。`assets/brand/motuo-mark-*.svg` 作为平台侧配置和后续品牌资源留存，不直接嵌入原生导航栏页面代码。
- 当前静态页面的真实加载完成点暂定为 `onReady`；如后续接入真实异步数据，可把 `markEntryReady()` 延后到真实数据 ready 回调中。

## 1.1.4 需求口径

- 交付包形态：静态 HTML/CSS 状态稿、design tokens、SVG 图标、状态截图
- 本地验收解包目录：`/tmp/ui-delivery-v1.1.4-review/ui-delivery-v1.1.4-visual`

  - `UI_DELIVERY.md`

### 已确认口径

1. 控制器代表色和排行榜颜色：以 UI 交付包为准。
2. 业务文案：以当前项目为准，`制动巡航` 不改为 UI 包中的 `自动巡航`。
3. 业务判断处的颜色规则：以 UI 交付包为准，包括软件和手感模块中的 good / warn / bad 颜色映射。

### 本次实现目标

- 原生抖音小程序页面视觉尽量还原 UI 交付包。
- 深色模式和明亮模式都需要适配。
- 顶部标题、导航、产品 chip、表格、排行榜、排序区、列选择区、说明弹窗、水印、底部说明等主要区域均按 UI 包更新视觉。
- 图标采用 UI 包交付的圆角线性 SVG 风格，优先替换当前硬编码颜色的旧图标。
- 产品高亮色、排行榜条形颜色、排行榜高亮颜色按 UI 包执行。
- 软件和手感模块中的业务颜色判断按 UI 包执行。
- 抖音原生顶栏中的 `反馈`、`三点`、`关闭` 等平台按钮需要纳入暗色模式适配；明亮模式保持平台默认白底黑字。
- 表格在选中任意高亮产品后仍需要支持横向滑动，右侧数据文字不得覆盖左侧固定型号列。
- 保留现有页面标题：`2026年春季260级控制器对比手册`。
- 保留现有水印：`小拓子`。
- 保留现有业务字段文案：`制动巡航`。

### 落地方式

- 不直接引入 UI 包中的 `data.js`、`icons.js`、`render.js` 作为生产代码。
- 不把 UI 包的浏览器 DOM 实现照搬进小程序。
- 前端只吸收 UI 包中的视觉规则、tokens、样式意图、SVG 图标和状态参考。
- `tokens.css` 中的主题变量需要转译到当前小程序 `.ttss` 体系中，兼容当前 `.app` / `.app.light` 主题切换方式。
- `styles.css` 中的浏览器专属写法需要按抖音小程序能力改写，不影响现有交互。
- 业务颜色规则可以通过现有 `textTone` 一类 helper 调整，但不得改变数据结构。

### UI 包中的明确例外

- UI 包将 `brakeCruise` 的 label 写为 `自动巡航`，本项目不采纳，仍使用 `制动巡航`。
- UI 包中的静态渲染脚手架仅用于设计预览，不进入生产代码。
- UI 包截图是设计验收参考，不等同于小程序最终运行截图；前端落地后必须重新在小程序页面中验收。

## 1.1.1 已实现需求

### 版本目标

1.1.1 版本目标是将当前 1.1.0 静态 HTML 页面迁移为符合抖音标准的原生抖音小程序项目。该目标已完成。

### 技术迁移要求

1.1.1 已从浏览器 HTML 写法迁移为小程序原生写法：

- 不使用 `window`
- 不使用 `document`
- 不使用 `innerHTML`
- 不使用浏览器 `localStorage`
- 不使用原生 HTML `table` 作为核心结构
- 不引入第三方前端依赖
- 不使用 `web-view`

页面结构使用抖音小程序组件，例如 `view`、`text`、`scroll-view`、`button` 等。交互使用 `bindtap`、`data-*`、`Page` 和 `this.setData`。

静态数据当前先放在页面 `index.js` 中，后续如数据量继续增大，再考虑拆分为更细的数据文件。

### 样式要求

- 使用 TTSS
- 移动端优先
- 优先使用 `rpx`

- 保留 1.1.0 的暗色视觉基调和亮色主题能力

- 首列固定效果如原生小程序实现成本过高，可以先用可读性优先的横向滚动方案替代，并在实现方案中说明取舍

### 本地状态

UI 验收已通过：采用「圆角容器 + 圆角线性 SVG」。最佳徽章采用「星标 + 最佳」，排名角标保留 `#1/#2/#3`。

涉及范围包括但不限于：

- 顶部工具图标
- 模块信息图标
- 小浮窗关闭图标
- 列显示图标
- 排序图标
- 主题切换图标
