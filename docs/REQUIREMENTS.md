## 背景

项目中目前保留一个原始静态 HTML 文件：`controller-review(1).html`。它用于展示控制器横向测试结果，页面内置静态数据、样式和交互逻辑。

当前已完成 1.1.2 视觉、交互和说明文案修补。后续需求仍先沉淀到文档，再按版本进入实现。

## 版本范围

- 当前版本：1.1.2
- 版本标签：`v1.1.2`
- 版本目标：完成原生抖音小程序迁移后的视觉、交互和说明文案修补
- 备份要求：每个版本都需要推送到 GitHub，并保留可回滚的版本标签

### 标题修改

- 顶部左上角大标题从 `2026 年春季控制线横屏对比手册` 修改为 `2026年春季260级控制器对比手册`
- 小程序系统导航栏标题需要同步调整为 `2026年春季260级控制器对比手册`
- 如运行时需要动态同步导航栏标题，使用抖音小程序 `tt.setNavigationBarTitle`
- 顶部左上角页面内标题字体需要调大一点，保持移动端不溢出
- 如标题在小屏设备上过长，允许自然换行，但不能遮挡右侧工具图标

### 序号与导航优化

标题下方 1-6 的可切换序号需要替换为对应模块标题简称。

建议导航文案：

- `1. 硬件`
- `2. 软件`
- `3. 手感`
- `4. 温控`
- `5. 耗电`
- `6. 加速`

验收标准：

- 导航项能横向滚动
- 当前模块高亮清晰
- 点击导航后仍能跳转到对应模块
- 文案不能被压缩成难读的竖排

### 明亮（日间）模式适配

- 详细排查日间模式下 SVG 图标颜色显示不正确的问题
- 明亮模式下图标需要跟随日间色彩体系，不能继续使用过亮的暗色模式图标颜色
- 切换至明亮模式后，抖音自带导航栏 Title 的底色需要同步切换为白色
- 明亮模式下小程序导航栏前景色需要与白色背景匹配，优先使用黑色前景
- 实现时优先使用抖音小程序 `tt.setNavigationBarColor` 动态同步导航栏颜色；同时保留 `app.json` / 页面 JSON 中的默认导航栏配置
- 导航栏颜色值必须使用完整 6 位十六进制；`frontColor` 按官方限制只使用 `#ffffff` 或 `#000000`

### 列表与图标样式

- `1. 硬件规格对比` 等二级标题右侧的信息图标和显示列图标需要去掉底色
- 二级标题右侧图标颜色需要调暗，弱化为辅助入口
- 图标仍需保持圆角线性 SVG 风格，但线条应比 1.1.1 更细
- 点击右侧“显示列”图标后，弹出项中的文字需要在垂直方向上与底色小块居中对齐
- 所有列筛选小块的高度、行高、内边距需要统一，避免文字上下偏移

### 表格与排行榜交互

- 表格 / 排行榜切换处，选中状态的图标颜色需要与文字颜色保持一致
- `交互软件与辅助功能` 模块中，横滑到最右侧 `驻车刹车灯` 时，`凌博 E260 Pro Max` 的长文案不能溢出表格边缘
- 长文案需要通过换行、固定宽度、截断或更宽列策略处理，优先保证可读性
- 第四个模块及所有带排行榜的模块，右侧 `升序/降序` 文字必须横向排列，不能被挤压成竖向
- 排行榜工具区需要为排序按钮预留足够宽度

### 全文内容与视觉调整

- 全文去掉 `改装` 字样
- `改装产品` 等语义需要替换为更合适的表达，例如 `参测控制器`、`升级控制器`、`对比控制器` 或按上下文重写
- 页面整体高亮色替换为图标蓝，主色参考蓝色图标圆形底色，当前 UI 稿主色为 `#4E67E8`
- 同步调整配色体系：底层背景、卡片深色、边框和暗色字体，需要替换为蓝色同色系；其他辅色统一改为低纯度、低明度的蓝灰体系
- 带主题色底色的选中标签、按钮和切换项，文字统一使用白色
- 底层背景和暗色内容面需要进一步降低蓝色感，当前 UI 稿建议底层背景为 `#101722`，暗色内容面为 `#171F2E`
- 除高亮色 `#4E67E8` 和明亮模式强调色 `#3F57C8` 外，其他辅色需要降低纯度和明度，不抢主色
- 保持测评报告风格，不做过度花哨的营销风
- 页面内所有 SVG 图标线条需要调细，整体更轻、更精致

### 水印恢复

- 在 1.1.2 中恢复水印，不回改历史版本标签
- 水印内容修改为 `小拓子`
- 水印样式为横向铺满、斜向密集
- 水印需要覆盖页面内容区域，但保持低透明度，不影响阅读
- 暗色和明亮模式下都需要可见
- 小程序页面和 1.1.0 对照 HTML 是否同步恢复水印，需要实现前再次确认；默认只修复当前原生小程序页面

### 控制器说明优化

#### 说明话术

- 点击标题右侧小图标展开的所有说明内容需要重写
- 重写时需要检索相关资料，并结合当前测试数据语义改成小白用户也能听懂的话术
- 说明不要堆技术名词，必须解释“怎么看、代表什么、有什么注意点”
- 重点解释：母线电流、相线电流、电压范围、软件功能、骑行手感、温控限流、稳定输出耗电、加速测试
- 说明文案需要避免绝对化结论，保留测试口径和参考边界

#### 交互方式

- 当前下方展开的说明浮窗需要改为页面正中心弹出
- 弹窗需要有关闭按钮
- 点击遮罩是否关闭可以在实现阶段决定，优先保证误触风险低

#### 视觉表现

- 浮窗弹出时，背景需要暗化处理
- 如果抖音开发者工具和目标端支持，可以使用高斯模糊；如果兼容性不稳定，则使用半透明暗色遮罩
- 弹窗内容需要有清晰标题、正文和适当留白
- 移动端小屏下弹窗不能超出屏幕，正文可滚动

## 1.1.1 已实现需求

### 版本目标

1.1.1 版本目标是将当前 1.1.0 静态 HTML 页面迁移为符合抖音标准的原生抖音小程序项目。该目标已完成。

本版本不再以 HTML 文件作为运行入口，也不使用 `web-view` 包裹 H5 页面。当前 `controller-review(1).html` 作为历史基线和对照页面保留，小程序运行入口改为原生小程序文件。

### 原生小程序项目结构

1.1.1 已新增以下结构：

```text
app.js
app.json
app.ttss
project.config.json
pages/controller-review/index.ttml
pages/controller-review/index.ttss
pages/controller-review/index.js
pages/controller-review/index.json
assets/icons/
```

页面路径需要在 `app.json` 中声明。页面由 `.ttml`、`.ttss`、`.js`、`.json` 组成，符合抖音小程序原生页面结构。

### 功能迁移范围

1.1.1 已从 1.1.0 迁移并保留以下能力：

- 标题：`2026 年春季控制线横屏对比手册`
- 页面级弱水印：`小拓子横评`
- 六个测试模块和静态测试数据
- 每个模块的说明图标和说明小浮窗
- 圆角线性 SVG 图标体系
- 产品高亮
- 主题切换
- 最佳徽章开关
- 排名角标开关
- 列显示控制
- 表格视图
- 排行榜视图
- 排序逻辑
- 九号 M395C 原厂作为参考项，不参与改装产品排名

### 继续移除的功能

以下功能在 1.1.1 中继续保持移除，不恢复：

- 聚焦模式和非高亮产品变暗逻辑
- 录制模式
- 截图按钮和截图提示入口

### 技术迁移要求

1.1.1 已从浏览器 HTML 写法迁移为小程序原生写法：

- 不使用 `window`
- 不使用 `document`
- 不使用 `innerHTML`
- 不使用浏览器 `localStorage`
- 不使用原生 HTML `table` 作为核心结构
- 不引入第三方前端依赖
- 不使用 `web-view`

页面结构使用抖音小程序组件，例如 `view`、`text`、`scroll-view`、`button` 等。交互使用 `bindtap`、`data-*`、`Page` 和 `this.setData`。

静态数据当前先放在页面 `index.js` 中，后续如数据量继续增大，再考虑拆分为更细的数据文件。

### 样式要求

- 使用 TTSS
- 移动端优先
- 优先使用 `rpx`
- 保持测评报告风格
- 保留 1.1.0 的暗色视觉基调和亮色主题能力
- 表格区域使用横向滚动容器模拟表格阅读体验
- 首列固定效果如原生小程序实现成本过高，可以先用可读性优先的横向滚动方案替代，并在实现方案中说明取舍

### 本地状态

1.1.0 中的浏览器 `localStorage` 状态已迁移为抖音小程序本地缓存能力，使用 `tt.getStorageSync` 和 `tt.setStorageSync`。

需要保存的状态包括：

- 主题
- 高亮产品
- 最佳徽章开关
- 排名角标开关
- 当前分区
- 各分区视图、排序、隐藏列等状态

说明小浮窗的打开状态不需要持久化。

### 后端判断

1.1.1 仍然不需要后端。

理由：

- 不需要用户登录

- 不需要服务端生成报告

如后续出现动态数据、后台配置、账号权限、数据提交或服务端生成图片/报告需求，再重新评估后端子代理。

- 顶部工具图标
- 模块信息图标
- 小浮窗关闭图标
- 列显示图标
- 排序图标
- 主题切换图标
